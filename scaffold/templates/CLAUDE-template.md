## Plugin: implr

This project uses the implr SDLC plugin. It automates the path from documentation to reviewed
code through a set of skills. All plugin artefacts live under `docs/implr/`.

**Do not edit these auto-managed files by hand:**
- `docs/implr/kb-index/` — KB registry, digests, and syntheses (doc-ingest)
- `docs/implr/requirements/` — generated requirements (ba-requirements-gen)
- `docs/implr/plans/` — implementation plans (dev-planner)
- `docs/implr/reviews/` — code review reports (dev-code-review)

**Reference material (safe to read, edit with care):**
- `docs/implr/config/implr.config.yaml` — plugin configuration
- `docs/implr/config/DEV-STANDARDS.md` — your development standards
- `docs/implr/schemas/` — canonical schemas for requirements, plans, reviews
- `docs/implr/templates/` — templates used by the skills

## Skills

| Skill | Purpose |
|-------|---------|
| `/implr-init` | Scaffold the plugin structure (run once per project) |
| `/doc-ingest` | Index and digest the knowledge base |
| `/arch-gen` | Generate ARCHITECTURE.md from the KB |
| `/ba-requirements-gen` | Generate requirements from the KB |
| `/dev-planner` | Create implementation plans from approved requirements |
| `/dev-executor` | Implement plans as production code |
| `/dev-code-review` | Review produced code in fresh context |

## How Claude Should Work Here
- When asked to implement something, check `docs/implr/requirements/` and `docs/implr/plans/`
  first for an existing requirement and plan before writing code.
- When asked about system behaviour, consult `docs/kb/` and the digests in
  `docs/implr/kb-index/`.
- Follow `docs/ARCHITECTURE.md` and `docs/implr/config/DEV-STANDARDS.md` for all code.
- Never edit auto-managed files directly; go through the relevant skill.
- Treat approved requirements and their plans as the source of truth for what to build.
